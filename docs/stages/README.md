# Этапы разработки

Каждый файл в этом каталоге — **самодостаточное задание на один этап**.
Его достаточно, чтобы начать работу в новом чате, не перечитывая
переписку и не восстанавливая контекст.

## Как начинать этап в новом чате

1. Прочитать `docs/WORKFLOW.md` — там окружение, порядок коммитов и
   правила работы с репозиторием.
2. Открыть файл нужного этапа из этого каталога.
3. Сверить состояние: `git log --oneline -5`, `git status`.
4. Выполнить этап и закоммитить по `WORKFLOW.md` §3.3.

## Правила для всех этапов

- **Коммит и пуш после каждого логического блока**, а не в конце этапа.
- **Пуш требует полного доступа к системе** — см. `WORKFLOW.md` §3.3.
- **Сообщение коммита — по-русски**, одна строка заголовка плюс тело
  при необходимости.
- **Числовые параметры протокола помечены `[ПРОВЕРИТЬ]`** — они
  согласованы архитектурно, но не проверены на железе. Не считать их
  окончательными.
- **Прошивка плат требует отдельного разрешения** каждый раз
  (`ESP32_C3_Mesh_Chat_Project_Plan.md` §9.3).

## Порядок, если не знаете, с чего начать

Начинать с **этапа 1 клиента**. Он не требует ни железа, ни USB-serial,
ни Node.js и даёт видимый результат быстрее всего. Прошивка подключается
параллельно и независимо: клиент и прошивка связаны только контрактом
`protocol/BLE_API.md`.
