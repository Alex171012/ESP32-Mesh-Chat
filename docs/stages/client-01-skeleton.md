# Этап 1 клиента — каркас

> **Требуется:** ничего, кроме браузера Chromium.
> **Железо:** не нужно.
> **Предыдущий этап:** нет.

## Цель

Создать структуру файлов клиента так, чтобы страница открывалась, не
падала и была готова к наполнению. Никакой логики — только каркас.

## Контекст

Клиент — статическое веб-приложение: HTML, CSS, JS без сборки. Один код
на десктоп и мобильные, различие — только через медиазапросы CSS.
Подробности — `docs/WEB_CLIENT_PLAN.md` §1–3.

## Что сделать

1. Создать дерево файлов по `docs/WEB_CLIENT_PLAN.md` §3. Все модули
   создаются сразу, даже пустые — это задаёт границы и не даёт потом
   свалить всё в один файл.
2. Разметить в `index.html` четыре обязательные области
   (`docs/WEB_CLIENT_PLAN.md` §5): состояние связи, лента, панель узлов,
   поле ввода. Пока с текстом-заглушкой.
3. В `css/base.css` завести переменные темы: цвета фона, текста,
   акцента, границ, шрифты, отступы. Все цвета — только через
   переменные, чтобы смена темы была правкой одного блока.
4. В `css/layout.css` — раскладка под десктоп и мобильный.
5. В `css/components.css` — заготовки классов для сообщений, узлов,
   индикаторов, кнопок.
6. В `js/config.js` вынести константы: UUID сервиса и характеристик,
   лимит 179 байт, тайм-ауты, режим транспорта (`?mock=1`).
7. `js/app.js` — точка входа: находит элементы, подписывается на
   события, вызывает заглушку модулей.

## Открытые решения

Три вопроса из `docs/WEB_CLIENT_PLAN.md` §7 не закрыты. Если ответа нет,
брать значения по умолчанию:

- **две колонки** (чат + узлы) — влияет на `layout.css`;
- **тёмная тема**;
- **маршрут в ленте**, под сообщением.

## Проверка

- Страница открывается двойным кликом по `index.html` и не даёт ошибок
  в консоли.
- Видны все четыре области.
- При сужении окна до ширины телефона раскладка перестраивается в одну
  колонку.
- В консоли `config.js` доступен и содержит лимит 179.

## Критерий готовности

Каркас открывается в браузере, ошибок в консоли нет, все модули
существуют, цвета берутся из переменных.

## Коммит

```
Каркас веб-клиента: структура, разметка, стили

Создано дерево файлов по плану клиента, размечены четыре
обязательные области интерфейса, заведены переменные темы и
базовые раскладки под десктоп и мобильный. Логики нет.
```
