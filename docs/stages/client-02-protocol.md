# Этап 2 клиента — кадрирование и JSON

> **Требуется:** браузер Chromium. Железо не нужно.
> **Предыдущий этап:** `client-01-skeleton.md`.

## Цель

Научить клиент собирать и разбирать кадры BLE-контракта, ничего не зная
о транспорте. Модуль `protocol.js` — чистые функции, проверяемые в
консоли.

## Контекст

BLE передаёт поток байтов без границ сообщений, поэтому границы задаёт
своё кадрирование. Спецификация — `protocol/BLE_API.md` §3.

```
[ SOF(1) | len(2) | payload(len) | crc16(2) ]
```

- `SOF` = `0x7E`
- `len` — длина `payload`, **little-endian**
- `crc16` — CRC-16/CCITT по `payload`

**Критично:** один write не равен одному кадру. Приёмник обязан
принимать байты частями и склеивать их по `len`. Начинать разбор
следующего кадра можно только после того, как получен весь текущий.

## Что сделать

1. `encode(obj)` — объект → кадр: JSON → UTF-8 → `len` → CRC → SOF.
2. `decode(bytes)` — обратный разбор с проверкой `SOF` и CRC.
3. Буфер приёма: `feed(chunk)` принимает произвольный кусок байтов и
   возвращает массив **готовых** кадров. Незавершённый хвост остаётся в
   буфере до следующего вызова.
4. Обработка мусора: если `SOF` не найден или CRC не сошёлся —
   сообщить об ошибке и продолжить поиск следующего `SOF`, не теряя
   поток.
5. Реализовать CRC-16/CCITT без внешних библиотек.

## Ловушки

- **Байты, не строки.** На входе и выходе `Uint8Array`. Перевод в строку
  только внутри JSON-разбора.
- **UTF-8 много: русская буква занимает 2 байта.** Считать длину в
  байтах, а не в символах, иначе лимит 179 будет нарушен незаметно.
- **`len` little-endian**, в отличие от порядка байтов в самом кадре.
- **Незавершённый кадр нельзя выбрасывать** — он придёт следующим
  куском.

## Проверка

Выполнить в консоли браузера (файл открыть как `index.html`):

```js
// Круговой рейс
const f = protocol.encode({ t: "ping", id: 7 });
protocol.feed(f)              // → [{ t: "ping", id: 7 }]

// Разбиение на куски по одному байту
let out = [];
for (const b of f) out.push(...protocol.feed(new Uint8Array([b])));
out                           // → один объект, несмотря на раздробленность

// Испорченный CRC
const bad = f.slice(); bad[bad.length - 1] ^= 0xFF;
protocol.feed(bad)            // → ошибка, не исключение
```

- Кадр с русским текстом длиной 179 байт проходит круговой рейс.
- Кадр, разбитый на 20-байтовые куски (как реальный BLE MTU), собирается
  верно.
- Два кадра подряд в одном куске возвращаются как два объекта.

## Критерий готовности

`protocol.js` — набор чистых функций без обращений к DOM и транспорту,
проверенных в консоли на всех случаях выше.

## Коммит

```
Кадрирование BLE на клиенте: SOF, длина, CRC-16/CCITT

Реализованы сборка и разбор кадров, буфер приёма для склейки
частей и восстановление после мусора. Модуль не зависит от
транспорта и проверен в консоли.
```
