# Этап 4 клиента — лента, маршрут, статусы

> **Требуется:** браузер Chromium. Железо не нужно.
> **Предыдущий этап:** `client-03-mock.md`.

## Цель

Главный экран: лента сообщений, у каждого — маршрут и статус доставки.
Это то, ради чего существует проект: показать, как сообщение идёт через
mesh.

## Контекст

**Четыре статуса** (`MESH_PROTOCOL.md` §6) — не украшение, а суть
интерфейса:

| В интерфейсе | Значение | Когда |
|---|---|---|
| принято шлюзом | `accepted` | плата приняла кадр по BLE |
| в пути | `sent` | ушло в эфир, ACK ещё нет |
| доставлено | `delivered` | ACK вернулся |
| не доставлено | `failed` / «не отправлено» | ACK не пришёл / связи не было |

Успешная отправка по BLE **не** означает доставку через mesh. Статусы
обязаны быть раздельными и видимыми.

## Что сделать

1. Лента: входящие и исходящие сообщения, прокрутка вниз при новом.
2 По своему сообщению — «Я», по чужому — имя узла. Системы пользователей
   нет (`BLE_API.md` §7.2), имя принадлежит плате.
3. **Маршрут под каждым сообщением.** Формат вида `1 → 2 → 3`. Маршрут —
   главный элемент демонстрации, он должен читаться сразу, а не
   прятаться за кликом.
4. Статус сообщения меняется по месту, без перерисовки всей ленты.
5. Счётчик времени: метка ставится **на клиенте** при получении
   (`MESH_PROTOCOL.md` §6.3). Часы узлов не синхронизированы, брать время
   из пакета нельзя.
6. Различать broadcast (`dst: 0`) и личное сообщение — визуально, но
   сдержанно.

## Ловушки

- **Не перерисовывать ленту целиком** на каждое событие: при потере
  пакетов и задержках это даёт мигание и сбивает прокрутку.
- **Порядок сообщений — по времени получения на клиенте**, а не по
  времени из пакета (`MESH_PROTOCOL.md` §7.2).
- **Маршрут может быть неполным** или отсутствовать у broadcast —
  интерфейс обязан это показать, а не нарисовать пустую стрелку.
- Интерфейс должен оставаться «красивым, но без лишнего»: маршрут
  компактной строкой, без рамок и подписей на каждый элемент.

## Проверка

На заглушке, `index.html?mock=1`:

- Отправить сообщение → статус проходит `принято шлюзом` → `в пути` →
  `доставлено`, меняясь на месте.
- У сообщения виден маршрут `1 → 2 → 3`.
- Дождаться потерянного пакета → статус `не доставлено`, лента не
  сломалась.
- Русский текст отображается корректно.
- Отправка broadcast и личного сообщения различаются визуально.

## Критерий готовности

Сценарий `1 → 2 → 3` виден в ленте с маршрутом и всеми четырьмя
статусами. Лента не мигает и не теряет прокрутку при потоке сообщений.

## Коммит

```
Лента сообщений: маршрут и четыре статуса доставки

Сообщения с маршрутом 1 → 2 → 3, поочерёдная смена статусов
принято шлюзом, в пути, доставлено, не доставлено, метки
времени ставятся на клиенте.
```
