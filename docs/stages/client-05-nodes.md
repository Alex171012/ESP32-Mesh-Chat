# Этап 5 клиента — панель узлов

> **Требуется:** браузер Chromium. Железо не нужно.
> **Предыдущий этап:** `client-03-mock.md` (можно параллельно с этапом 4).

## Цель

Показать, кто в сети и как до него добраться. Панель узлов — второй по
важности элемент после маршрута: она объясняет, почему сообщение идёт
через переход.

## Контекст

Список **обязан** быть разделён на две группы
(`docs/WEB_CLIENT_PLAN.md` §5, `BLE_API.md` §4.2):

| Группа | Смысл |
|---|---|
| **рядом** | прямые соседи, слышны напрямую |
| **через mesh** | достижимы только через промежуточный узел |

Разделение не косметическое. Оно показывает топологию: узел «через mesh»
и есть причина появления маршрута в ленте.

## Что сделать

1. Две группы с заголовками, узлы внутри — имя и `node_id`.
2. Обновление по событию `nodes`, без перерисовки вручную.
3. Узел без имени показывать как `Узел <node_id>`
   (`BLE_API.md` §4.1) — это нормальное состояние нового узла, а не
   ошибка.
4. Online/offline: узел, не подававший признаков жизни дольше порога,
   помечается offline и не исчезает сразу — иначе список будет мигать
   (`MESH_PROTOCOL.md` §5).
5. **Выбор получателя.** Переключатель «Всем / узлу» рядом с полем ввода
   (`BLE_API.md` §7.1). По умолчанию — «Всем», `dst: 0`. Выбор
   конкретного узла берётся из этой панели.
6. Кнопка смены имени своего узла — точка входа для этапа 8
   (`BLE_API.md` §7.3–7.4).

## Ловушки

- **Не путать прямой и mesh-путь.** Если узел слышен напрямую, он в
  первой группе, даже если достижим и через ретрансляцию.
- **Узел 3, слышимый узлом 1 напрямую, ломает демонстрацию маршрута** —
  это известный риск (`ESP32_C3_Mesh_Chat_Project_Plan.md` §13). В
  интерфейсе разделение групп как раз делает такое видно.
- Offline-узел не удалять из списка мгновенно.

## Проверка

На заглушке, `index.html?mock=1`:

- Видны две группы, заполненные верно, узлы безымянные показаны как
  `Узел <id>`.
- Через ~минуту узел 3 уходит в offline, пометка появляется сама.
- Переключатель «Всем / узлу» меняет `dst` в отправляемом кадре:
  проверить в консоли на `send()`.
- При выборе узла из группы «через mesh» маршрут в ленте непустой.

## Критерий готовности

Панель разделяет соседей и mesh-узлы, обновляется автоматически,
показывает offline и служит источником выбора получателя.

## Коммит

```
Панель узлов: соседи и mesh раздельно

Список узлов разделён на прямых соседей и достижимых через
ретрансляцию, добавлены пометки offline, безымянные узлы
показаны по номеру, выбор получателя перенесён в панель.
```
