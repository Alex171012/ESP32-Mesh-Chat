# Этап 6 клиента — разрыв связи и «Повторить»

> **Требуется:** браузер Chromium. Железо не нужно.
> **Предыдущий этап:** `client-04-feed.md`.

## Цель

Клиент должен вести себя достойно, когда связь рвётся: показать это,
заблокировать ввод, восстановиться и не потерять написанное.

## Контекст

Правила — `protocol/BLE_API.md` §6.2–6.4.

| Ситуация | Поведение |
|---|---|
| Связь потеряна | индикатор, ввод заблокирован, автопереподключение |
| Сообщение при разрыве | статус «не отправлено», кнопка «Повторить» |
| Переподключение | задержки 1, 2, 4, 8, 16 с, далее каждые 30 с |
| Узел занят другим клиентом | `{"t":"err","code":"busy"}` — понятный текст |

**Ключевое правило:** неотправленное сообщение **никогда не отправляется
автоматически**. Только вручную кнопкой «Повторить». Пользователь должен
видеть, что именно не ушло.

## Что сделать

1. Индикатор состояния связи — **виден всегда**
   (`ESP32_C3_Mesh_Chat_Project_Plan.md` §10), рядом имя шлюза.
2. При разрыве: блокировать поле ввода и отправку, но **не стирать**
   набранный текст.
3. Сообщения, не ушедшие из-за разрыва, получают статус «не отправлено»
   и кнопку «Повторить».
4. Автопереподключение с нарастающей задержкой: 1, 2, 4, 8, 16 с,
   затем каждые 30 с. Показывать обратный отсчёт или хотя бы факт
   попытки.
5. Обработать `busy`: понятный текст вида «Узел занят другим
   подключением», без технического кода в интерфейсе.
6. Ошибки из `{"t":"err"}` показывать человеческим языком.

## Ловушки

- **Событие разрыва приходит и при нормальном завершении** — не
  показывать ошибку, если пользователь отключился сам.
- **Автоподключение невозможно.** Web Bluetooth требует жеста
  пользователя (`BLE_API.md` §1): после перезагрузки страницы
  `connect()` вызывается только по клику. Автопереподключение работает
  только в пределах живой страницы.
- `busy` — не ошибка пользователя, а нормальная ситуация: узел занят
  другим телефоном.

## Проверка

На заглушке, `index.html?mock=1`:

- `mock.forceDisconnect()` → индикатор меняется, ввод блокируется,
  набранный текст на месте.
- Отправка в этот момент → статус «не отправлено», кнопка «Повторить».
- Восстановление связи → «Повторить» отправляет сообщение, статус
  проходит обычные четыре шага.
- Проверить нарастание задержек по логу в консоли.
- Имитировать `busy` → в интерфейсе понятный текст.

## Критерий готовности

Разрыв связи виден, ввод блокируется, неотправленное не теряется и не
уходит само, переподключение идёт с нарастающей задержкой.

## Коммит

```
Разрыв связи: индикатор, блокировка ввода, «Повторить»

Добавлены состояния соединения, автопереподключение с
нарастающей задержкой, статус «не отправлено» с ручным
повтором и понятная обработка ошибок busy и err.
```
