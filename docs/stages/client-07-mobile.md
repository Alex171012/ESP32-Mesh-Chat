# Этап 7 клиента — адаптив под мобильный

> **Требуется:** браузер Chromium. Железо не нужно. Для проверки на
> телефоне нужен адрес в сети (см. ниже).
> **Предыдущий этап:** `client-04-feed.md`, `client-06-reconnect.md`.

## Цель

Один и тот же код должен хорошо выглядеть на ноутбуке и на телефоне.
Отдельного мобильного клиента нет — только медиазапросы CSS.

## Контекст

Решение зафиксировано: **один код, два режима отображения** через
медиазапросы, а не два приложения (`docs/WEB_CLIENT_PLAN.md` §1, §3).
Логика, разметка и данные общие; различается только раскладка.

## Что сделать

1. Три режима: десктоп (две колонки), планшет, телефон (одна колонка).
2. На телефоне панель узлов уходит в выдвижную панель или вкладку —
   лента остаётся главной.
3. Поле ввода удобно для пальца: достаточная высота, не уезжает под
   экранную клавиатуру.
4. Учесть безопасные зоны выреза экрана (`env(safe-area-inset-*)`).
5. Проверить, что маршрут остаётся читаемым на узком экране.

## Ловушки

- **Телефон не откроет `localhost` компьютера** (`BLE_API.md` §1).
  Для проверки на Android нужен адрес машины в сети, например
  `http://192.168.x.x:5500`, а для реального BLE — HTTPS или туннель.
  Заглушка работает и по обычному `http`.
- **Экранная клавиатура** перекрывает нижнюю часть экрана — поле ввода
  не должно оказываться под ней.
- Не дублировать разметку под мобильный: режим задаётся только CSS.

## Проверка

- В DevTools включить режим устройства и пройти по ширинам 320, 375,
  768, 1280 px — раскладка перестраивается, ничего не обрезано.
- Маршрут `1 → 2 → 3` читается на ширине 320 px.
- Поле ввода доступно после открытия клавиатуры.

## Критерий готовности

Интерфейс пригоден на телефоне без отдельной сборки и без правок
логики.

## Коммит

```
Адаптив под мобильный: одна колонка и выдвижная панель узлов

Добавлены медиазапросы для трёх режимов, учтены безопасные
зоны экрана, поле ввода не перекрывается клавиатурой. Код и
разметка общие с десктопом.
```
